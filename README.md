# Doodle Dash

Multiplayer drawing and guessing game, 2–8 players per room. Zero dependencies: Node HTTP + a minimal WebSocket server.

- `npm test` — real multiplayer integration tests (8 simulated clients)
- `npm start` — serve on `$PORT` (default 8080)
- Server is authoritative for words, timers, scores and stroke history; the word is only sent to the drawer (and to everyone at round end).
- Env: `CHOOSE_MS`, `DRAW_MS`, `RESULT_MS`, `GRACE_MS` tune timers (tests use small values).

## Topic catalog, history and adaptive difficulty

- `catalog.js`: 1000+ distinct drawable topics in three base tiers (easy 1x, medium 1.5x, hard 2x). Topic id = slug of the name and is stable; never rename, only add. `test/history.test.js` checks count, tier sizes, duplicate/plural/synonym families and numbered labels.
- **Persistence** (`DATA_DIR`, default `/data` in the image; unset = in-memory only): `history.jsonl` (append-only, fsync per line, torn last line dropped on load, atomic compaction keeping the latest 20000 drawings) and `state.json` (+`.bak`, atomic tmp+rename) for tier overrides and the audit trail (latest 1000 changes). Single writer only: deploy with `Recreate`, one replica. SIGTERM/SIGINT closes in-flight drawings as `abandoned` and exits.
- **Per-drawing record** (anonymous): topic id, tier and multiplier at selection, start/end ms, duration, random per-game id, eligible guessers at start/end, correct count, guess times (ms since start), ink yes/no, drawer-dropped flag, outcome (`all`, `timeup`, `drawerLeft`, `abandoned`). Never stored: names, IPs, tokens, chat text, strokes, room codes. A start with no end (crash/restart) loads as `abandoned`. A turn skipped before a topic was picked records nothing.
- **No-repeat**: each offer reserves one topic per tier in memory across all rooms (synchronous, so two rooms never get the same topic); only the picked topic is recorded, unchosen offers are released and not burned. Per tier: never-drawn topics first, then topics outside the latest 1000 started drawings, and only if every unreserved topic of the tier was drawn within that window, the least recently drawn (exhaustion). Hence a player who always takes the hard offer sees no repeat for the first N_hard hard drawings (N_hard = current hard-tier size, about 350), then a strict least-recently-used cycle (each topic repeats roughly every N_hard hard drawings, minus topics currently reserved by other rooms). It cannot avoid repeats among 1000 all-hard drawings because the hard tier is smaller than 1000. Retention limit: history older than the latest 20000 drawings is forgotten. A catalog change that adds topics makes them unused immediately.
- **Adaptive tiers** (`adapt.js`, rules v1): per drawing solve index = correct/eligible x (1 - 0.5 x mean guess time / draw budget). Fair trials only: ended normally (`all`/`timeup`), drawer never dropped, ink drawn, at least half the eligible guessers stayed. Evidence = latest 100 fair drawings since the topic's last move, averaged per game then across games (SE with a 0.15 SD floor). Needs >= 20 fair drawings and >= 3 games. Moves one tier step only if the one-sided 90% bound clears the threshold: easy->medium if upper < 0.45, medium->hard if upper < 0.22, medium->easy if lower >= 0.70, hard->medium if lower >= 0.45. At most 6 moves per rolling 24 h; no tier may drop below 20% of the catalog. Thresholds are uncalibrated defaults, not fitted to data. Active turns keep the multiplier they were offered; history keeps the tier at selection; every move is appended to the audit trail. There is no admin or reset endpoint; `/stats` is aggregate-only.
